# Day 5 log: shapes, the hard way

**2026-11-05** · `5_shape_inspect/numpy_ops/shapes.py` · done

Today was meant to be the easy NumPy day. It turned into a list of small mistakes, each of which taught me
more than the task that caused it. So this log goes through them in the order I made them.

## 1. `python3 shapes.py` couldn't find the file

The file was in `numpy_ops/`, and I was one folder up. That's trivial, but it made me settle how each day
should be run: from the day's folder, as a module (`python -m numpy_ops.shapes`). That's the same way Day 4
runs, and it keeps package imports working.

## 2. A variable that only existed inside a function

My first `inspect_tensor` returned `shape, ndim`, and then I printed `name`, `shape` and `ndim` under
`__main__`. That's a `NameError`: those names only exist inside the function. The spec wanted a function that
prints and returns `None`, so I moved the `print` inside.

## 3. Twelve numbers don't fit in six boxes

```
ValueError: cannot reshape array of size 12 into shape (2,3)
```

I'd copied `np.arange(12)` from Task 2 into Task 3, where the matrix is `(2, 3)`. Reshape never adds or drops
data. The product of the new shape has to equal `size`, which is why `reshape(-1, 4)` can work out the missing
number.

## 4. Code at the top level runs on import

Tasks 2–5 sat at module level. Running the file was fine, but `import numpy_ops` would have printed
everything, run a one-second benchmark and (while bug 3 was there) crashed the test suite before a single
test ran. Each task is now a function, and `__main__` calls them. **A module should do nothing when imported
except define things.**

## 5. `outer_add` that wasn't an outer add

I called `outer_add(A, column_vect)` with `A` shaped `(3, 4)`. The answer was the right shape, so nothing
complained, but only the column was stretching. With `r` shaped `(1, 4)`, both inputs stretch, and that's
the point of the exercise. A correct output shape doesn't prove the computation was the one I meant, which is
today's lesson again in miniature.

## 6. A second `pyproject.toml`

The day's folder came with an empty one. Recent pytest treats any `pyproject.toml` as a sign of the project
root, so this one could have made pytest ignore the real config at the top of the repo. I made the same
mistake on Day 4. I deleted it and pointed the root config at `5_shape_inspect` (I had first typed
`5_numpy`, the folder name from the brief).

## Things that surprised me

- `np.array(5).shape` is `()`, but its `size` is 1. Zero dimensions doesn't mean zero elements.
- `x[11]` on a NumPy array returns a NumPy scalar of shape `()`, not a Python `int`.
- Broadcasting doesn't copy. `np.broadcast_to(b, (3, 4))` is a view with stride 0 along the new axis, which is
  why the faded rows in the diagram are drawn dashed.
- `AxisError` subclasses both `ValueError` and `IndexError`, so `sum(axis=2)` on a 2-D array can be caught as
  either.
- The loop version of element-wise multiply raises `IndexError` on mismatched shapes, and NumPy raises
  `ValueError`. Same mistake, different error, and the tests check both.
- Pillow merges identical frames when it writes a GIF. I drew 98 frames and the file has 50, because the pauses
  collapsed into longer single frames.

## Numbers worth remembering

On a `(1000, 1000)` array, vectorized NumPy was about **250x** faster for element-wise multiply and about
**450x** faster for row means. The row mean gap is wider because the loop does a Python `+=` per element and
NumPy does a single reduction in C.

## Open questions

- `X.sum(axis=1)` gives `(2,)`, and `X - X.sum(axis=1)` then fails or silently broadcasts the wrong way.
  `keepdims=True` fixes it. Is there a habit that makes me reach for `keepdims` before the bug, not after?
- Row-major means `X[i, :]` is contiguous and `X[:, j]` isn't. How much slower is summing columns than rows on
  a large array, and does `np.asfortranarray` flip it?
- `einsum` from Day 2 writes the shapes into the call itself (`"bij,bjk->bik"`). Would shape bugs be rarer if
  every matmul in a model were written that way?
