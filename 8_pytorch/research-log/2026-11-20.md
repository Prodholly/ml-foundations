## the bug worth remembering: one argument to `kaiming_normal_`

the brief said `nn.init.kaiming_normal_(w, mode="fan_out", nonlinearity="relu")`, so that's what the first CIFAR run used. it finished at 86.62%, above target, and i almost moved on. then i noticed three things that didn't fit:

1. the first epoch's train loss was **15**. a 10-class model that knows nothing should sit around ln(10) ≈ 2.3.
2. in the init comparison, kaiming fan_out was the *worst* scheme, at 26.7%, behind even the deliberately bad gaussian 0.01.
3. its gradient at step 0 was ~90, when every other scheme was in single digits.

the cause is the network's shape. fan_out scales each weight matrix by its number of outputs, and my MLP narrows: 3072 → 1024 → 512 → 256 → **10**. the last layer has fan_out = 10, so its weights get std √(2/10) ≈ 0.45, when fan_in would give √(2/256) ≈ 0.09. that's 5× too big. the logits explode, the first few SGD steps are huge, and my best guess is that most relus get pushed into the zero region and stay there.

switching to fan_in (phase 1's he):

| | fan_out | fan_in |
|---|---|---|
| MLP, 5 epochs, val acc | 26.7% | 52.5% |
| cnn, epoch-1 train loss | 15.2 | 3.7 |
| cnn, final test acc | 86.62% | **90.50%** |

the cnn still trained with fan_out because batch norm re-normalizes after every conv. only the final linear layer was badly scaled, and AdamW's per-parameter steps seem to have worked around it. so the target was "met" with a bug in it. lesson: a loss that starts far above ln(classes) is a bug report, even when the final number looks fine.

## smaller things that bit, in the order they happened

- **gaussian init "didn't vanish."** in phase 1 the epoch-mean gradient norms looked normal for every init. momentum climbs out of a tiny init within a few hundred steps, so the epoch average hides it. logging one batch at step 0, before any update, showed the 130× gap at once. i used plain SGD for the experiment because Adam divides by the gradient's own size and would hide it anyway.
- **activation gradient checks failing at 3e-7.** relative error divides by |a| + |n|. where f′(x) ≈ 0 (deep in gelu's left tail), tiny absolute differences become large relative ones. i loosened the bar to the brief's 1e-5 instead of trusting a check that punishes flat regions.
- **`requires_grad()` vs `requires_grad_()`.** the first is a boolean attribute, so calling it raises `TypeError`. the second flips the flag in place. order matters too: scale the weights *first*, then call `requires_grad_()`. otherwise W is no longer a leaf and `W.grad` stays `None`.
- **`torch.rand` instead of `randn`.** uniform [0, 1) means every weight starts positive. nothing crashes, the verify script passes, and training is just quietly worse.
- **late binding in hooks.** `lambda grad: log[i].append(...)` inside a loop makes every hook write to the last layer, because the lambda looks up `i` when it runs, not when it's created. `lambda grad, i=i:` freezes it.
- **`LambdaLR` takes a one-argument function.** the brief passes `warmup_cosine(step, warmup_steps, total_steps)` directly, which fails. `functools.partial` binds the other two.
- **mps and cpu start from different weights.** `torch.manual_seed` seeds both, but each device has its own generator. so the two phase 2 runs differ slightly (97.64% vs 97.91%) even with the same seed.
- **checkpoint resume only matched once i saved the random state.** model, optimizer and scheduler state alone gave a different loss after resuming, because the shuffle order and the dropout masks changed. saving the torch / numpy / python random number generator states plus the `DataLoader` generator made it identical to the last digit.

## choices i made on purpose

- **a cnn for the benchmark.** the brief asked for an MLP above 85%. flattening a 32×32 image throws away which pixels are neighbors, so i kept the MLP for every comparison and used a small residual cnn (1.6M params, half the resnet-9 widths) for the final number. at full width it ran ~55 s per epoch on the m2, and half width ran ~19 s.
- **shuffle by default, the weighted sampler as an option.** CIFAR-10 is already balanced. `WeightedRandomSampler` draws with replacement, which skips about a third of the images every epoch. it's built and tested (it turns a 9:1 set into ~50/50), and `balanced=True` turns it on.
- **tensors on the device for the comparison experiments.** the init, optimizer and amp comparisons run many short trainings. loading CIFAR once as normalized tensors on mps, with no PIL and no workers, made them several times faster. the final run still goes through the real `DataLoader` and augmentation.
- **no bias before batch norm.** batch norm subtracts the mean, which cancels any bias. dropping it saves parameters, and the parameter-count formula and its test account for it.
- **one sync per epoch, not per batch.** `.item()` waits for the gpu to catch up. calling it every batch, in the hooks and the loss logging, made the gpu sit idle. everything accumulates as tensors on the device and converts once per epoch.
- **my own compute graph drawing.** torchviz needs the graphviz binary, so instead of installing system packages i walk `loss.grad_fn.next_functions` and lay the graph out with matplotlib. if torchviz is installed, it's used instead.

## the brief's checklist, one line each

- **dL/dW for a linear layer:** Z = XWᵀ + b, so W[o, i] collects X[n, i] · dL/dZ[n, o] over all n, which is dL/dZᵀ X.
- **he 2/fan_in vs xavier 2/(fan_in + fan_out):** relu zeroes half its inputs, so he doubles the variance to keep the forward signal steady. xavier averages forward and backward for symmetric activations.
- **why (p − y)/N:** the softmax jacobian and the log's 1/p cancel, leaving prediction minus target, averaged over the batch.
- **Adam's bias correction at t = 1:** m and v start at zero. without dividing by (1 − βᵗ), the first steps would be ~10× (m) and ~30× (v) too small.
- **AdamW:** decay on the weights directly, so it isn't rescaled by Adam's 1/√v. with L2 in the gradient, weights with large gradients would barely decay.
- **requires_grad:** every op on such a tensor records a node with what backward needs.
- **no_grad for updates:** otherwise the update itself becomes part of the graph, and in-place changes to a leaf raise an error.
- **retain_graph:** backward frees the graph. keep it only when you need a second backward through the same graph.
- **detach:** the same data, cut off from the graph. used for logging, for targets, and to keep the best weights.
- **nn.Parameter vs register_buffer:** both are saved and moved with `.to()`, but only parameters are trained.
- **why eval() changes dropout and batchnorm but not Linear:** eval only flips `.training`, and only those two modules read it.
- **GradScaler and unscale_:** the loss is multiplied up so fp16 gradients don't underflow to zero. you have to divide back before clipping, or max_norm is compared against inflated gradients.
- **filter normalization:** relu nets don't change if one layer is scaled up and the next scaled down. per-filter rescaling makes a step of 1.0 mean the same thing everywhere.
- **autograd.Function vs nn.Module:** a Function defines new math, its own forward *and* backward. a Module just arranges existing ops and holds parameters.
