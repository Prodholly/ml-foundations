# Day 7 log: every loss is a likelihood in disguise

**2026-11-14 → 2026-11-16** · `7_prob_stats/` · done

The idea that organized the whole day: the losses used for six days were never arbitrary. MSE is a Gaussian
negative log-likelihood, cross-entropy is a Bernoulli one, and the L2 penalty is a prior. Once that was clear, the
build order more or less wrote itself.

## The chain

Each piece leans on the one before. The order mattered more than any single function.

1. **MLE first** (`distributions.py`). The simplest version of "pick the parameters that make the data most
   likely", on a Gaussian and a coin.
2. **MAP next** (`bayes.py`). Five tails and no heads gives an MLE of exactly 0, the smallest possible case of
   overfitting. A Beta prior fixes it with pseudo-counts.
3. **Information theory** (`information.py`). Cross-entropy is the quantity the classifier minimizes, so it had to
   exist, and be trustworthy, before the classifier did.
4. **Objectives** (`losses.py`). These are the pass 1 likelihoods, rewritten as means with a penalty. The penalty
   is the pass 2 version of the Beta prior.
5. **One optimizer** (`optim.py`), validated on linear regression against the exact closed-form answer before it
   was trusted on logistic regression, which has no closed form.
6. **Metrics and splits**, because a model is only as honest as the number reported for it.
7. **Experiments** that put the whole stack under controlled conditions.

The model layer reuses pass 1 rather than reimplementing it:
- the residual variance is `mle_gaussian`;
- the log-likelihood is `log_likelihood_gaussian`;
- the logistic training loss is `cross_entropy_batch`.

One implementation per quantity means a bug can only live in one place.

Earlier days show up too:
- **Day 6:** the finite-difference gradient check reappears as a test, next to a much stricter `torch.autograd`
  check.
- **Day 5:** the vectorization benchmark grew into the timing sweeps.

## Decisions, and why

| decision | why |
|---|---|
| one `_validation.py` for every input check | each function states its shape contract once, and every function fails the same way |
| MLE variance divides by n, not n − 1 | it's what maximum likelihood gives. The tests pin it against numpy and torch, whose defaults differ |
| zeros masked out in entropy, never nudged by epsilon | a point mass should have entropy exactly 0.0, and `inf` is the correct cross-entropy when q rules out what p allows |
| log loss computed from logits with `logaddexp` | the probability route gives log(0) = −inf on confident predictions |
| convergence judged on the gradient, not the loss | a small loss change can just be a small step |
| `gradient_descent` raises on divergence | a silent `nan` would quietly flow into every downstream number |
| no `fit_transform` on the Standardizer | it makes "fit on the training rows" the only possible call sequence |
| oracles (torch, sklearn) only in `test_oracle.py`, all float64 | the library stays NumPy-only, and float32 would hide errors under 1e-7 |
| hypotheses written before running anything, with falsification criteria | otherwise any result can be narrated as expected |
| learning rate, iteration budget, tolerance and binning fixed for every run | a result should never be attributable to optimizer settings |
| paired design: same data and split for every λ in a replicate | it removes between-dataset noise from the comparison being measured |
| seeds derived from `MASTER_SEED` + run coordinates | any single run can be rebuilt from its log row |
| JSONL logs, one row per run | different experiments log different fields |
| fastest-of-3 timings in the benchmark | noise only ever adds time |
| a Makefile | the whole day reproduces from one command |

## What broke, in order

1. **`ModuleNotFoundError: prob_stats`.** The script was run as a plain file, so Python only searched
   `examples/`. Fixed by running from the root with `PYTHONPATH`, which the Makefile now does.
2. **`arr == 0.0 | arr == 1.0`.** `|` binds tighter than `==`, so this computed `0.0 | arr`, a bitwise OR on a
   float. It needs a pair of parentheses around each comparison.
3. **The variance guard checked `mu`.** A zero variance slipped through and became a `ZeroDivisionError`.
4. **"sanme shape".** A typo in an error message, caught because a test matches on the text.
5. **Two tests asked for the impossible.**
   - A random 10-sample draw came out exactly 5/5. Under a Beta(5, 5) prior, MAP and MLE are then both 0.5, so
     their "gap" was 0.
   - Another test expected a U-shaped posterior, which can't happen once there's any data, because every
     observation adds 1 to one of the Beta parameters.
6. **`np.linalg.solve` didn't raise on a singular system.** With 5 rows and 20 features, $X^\top X$ is singular
   in exact math, but in floating point its condition number was 4.5e17, not infinity. `solve` returned garbage
   without complaint. An explicit rank check now catches it.
7. **The separable-data test was too strict.** Without a penalty the weight does diverge, but only
   logarithmically: 2.5 after 5k steps and 3.1 after 50k. The test now checks the signature of that divergence
   ("more steps, bigger weight") instead of a fixed 5× ratio.
8. **E1 crashed at λ = 2.15, iteration 2,469.** Gradient descent on $\lambda\lVert\theta\rVert^2$ is only stable
   while $\eta(L + 2\lambda) < 2$. With $\eta = 0.5$ fixed, that caps λ near 1.7.
   - The two options were to lower the learning rate everywhere, or to cap the grid at 1.
   - The grid was capped, because the fixed learning rate is part of the experimental control.
   - The cost: ECE's minimum now sits on the grid edge, so it's only a lower bound on where calibration peaks.
9. **Saved in the editor, not on disk.** Twice, the code on screen wasn't the code that ran. Auto Save is on now.

## Numbers worth keeping

- **H1:** test log loss falls from 6.28 nats unpenalized to 0.60 at λ\* = 0.086, a 90% drop. Validation picked
  the same λ as test.
- **H2:** λ\* goes 0.159 → 0.0022 as n goes 100 → 3,200, a rank correlation of −1. The log-log slope is about −1.2,
  against the −1 predicted by $\tau^2 = 1/(2n\lambda)$ for a fixed prior.
- **H3:** at n = 100, honest AUC is 0.61. Leaking the scaler gives 0.61, but leaking feature selection gives 0.85.
- **B2:** the closed form's $d^3$ never showed up. At n = 5,000 and d ≤ 400, building $X^\top X$ ($n d^2$) costs
  more than solving it ($d^3$).

The selection-leak number is the one I keep coming back to. A model that's barely better than a coin gets reported
as good, and nothing about the code looks wrong.

## Open questions
